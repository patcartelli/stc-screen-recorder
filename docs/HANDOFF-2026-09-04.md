## Working on Linux without `swiftc`

No committed config does this — `vitest.config.ts`'s `globalSetup` calls
`helper/build.sh`, which needs a Swift toolchain this container does not
have. The workaround used all session is a small, deliberately **uncommitted**
scratch file at the repo root:

```ts
// vitest.linux.config.ts
import { defineConfig } from "vitest/config";
const ROOT = "/home/user/stc-screen-recorder/";
const resolve = { alias: { "@transform": ROOT + "transform/src" } };
const EXCLUDE = ["**/node_modules/**", "**/*.grant.test.ts", "**/*.slow.test.ts",
  ROOT + "helper/test/**", ROOT + "app/test/helper-client.test.ts", ROOT + "app/test/supervisor.test.ts"];
export default defineConfig({
  test: {
    root: ROOT, exclude: EXCLUDE,
    projects: [
      { resolve, test: { name: "unit", root: ROOT,
        include: ["transform/test/**/*.test.ts", "app/test/**/*.test.ts"],
        exclude: [...EXCLUDE, "**/*.e2e.test.ts"], testTimeout: 15_000 } },
      { resolve, test: { name: "e2e", root: ROOT,
        include: ["app/test/**/*.e2e.test.ts"], exclude: EXCLUDE,
        fileParallelism: false, testTimeout: 15_000 } },
    ],
  },
});
```
Run with `npx vitest run --config vitest.linux.config.ts --project unit`.
**This file kept disappearing between tool calls in this session** for
reasons never root-caused (not a git operation — `git status` showed it gone
with nothing to explain it). If it's missing, recreate it from the block
above rather than searching for a "lost" file. It excludes `helper/test/**`
wholesale even though a few files there (`stop-bounds.test.ts`,
`anchors.test.ts`'s non-Swift assertions) don't strictly need a compiler —
worth a narrower exclude list if this becomes a recurring need rather than a
one-session workaround.

Some `helper/test/*.ts` files ONLY read Swift source as text (regex, no
compilation) — `stop-bounds.test.ts` is one. Those genuinely can run on
Linux with a standalone one-file vitest config (no `globalSetup`); useful for
mutation-verifying a Swift constant's guard without a Mac, as done for
STC-304's `shutdownBackstopMarginSeconds` this session.

## One thing worth carrying forward

**A green CI check and a plausible-sounding fix are not the same as a correct
one**, especially for concurrency code nobody in this session could compile
or run. The STC-305 PR looked done — ticket's acceptance criteria addressed,
tests written, CI green — and a real review pass (not just re-reading my own
diff) found a genuine crash-class regression the ticket itself never
described, in the exact race window the fix was supposed to close. Before
merging any Swift concurrency change from a session that cannot compile
Swift, get a second, adversarial pass on it — the code-review skill, or
equivalent — rather than trusting a clean CI run alone. It is markedly
cheaper than finding out on the Mac, or worse, in production.
