## 1. Where this actually stands

**In the repo's own terms, phases 0–3 are complete and that claim is accurate.** A single-display
macOS recorder with an opt-in camera PiP, a deterministic cursor-overlay transform shared by
preview and export, non-destructive trim, a take library, and an unusually heavy verification
apparatus (four browser gates, a cross-process export-identity check, a writer-race harness,
mutation-tested guards). The core contract — `render(project, session, t)` pure, two sinks — holds
under audit: I found **no** wall-clock, animation-frame or accumulator leak inside the transform,
and every defect I did find is at a seam (the quit path, IPC boundaries, warning routing, the
preview's request queue). That is the normal place for defects in a codebase whose centre is
sound, and it is a better state than the handoffs' tone suggests: the 2026-08-31 handoff is a list
of wrong measurements, and none of them were wrong code.

**Against the brief I was handed, this is a different product.** There is no brief in the repo — no
`README.md`, no `decisions.md`; the closest things are `PHASE-1.md` → "Settled by phase 0" and
`CLAUDE.md`, which is a handoff log. The locked decisions in the prompt (`recording.json` as a
segments array with replaceable media ids, mic capture, two-stage auto-zoom, macOS 26 floor,
WebGPU/WGSL, SolidJS) appear **nowhere** in the tree — not as code, not as a plan, not as a
non-goal. What exists instead: `anchors.json` + `events.json` + `project.json` per take, media
referenced by filename, Canvas 2D compositing, a 600-line vanilla-DOM renderer, and a helper built
against the macOS 13.3 SDK with `-target arm64-apple-macos13.0`. So the honest stage is: *the
capture and determinism foundation the brief's editor would sit on is finished and verified; the
editor has not started, and its schema prerequisite is the one thing that gets more expensive the
longer it waits.* That mismatch is finding 0 below.

### 1. Quitting mid-take lost the take, silently — FIXED
- **Where:** `app/src/main.ts` (`before-quit`, `window-all-closed`), `app/src/supervisor.ts`
  (`shutdown`), and the helper's own `shutdown` at `helper/src/main.swift:253-258`.
- **Failure:** Cmd-Q while recording. `before-quit`'s listener was `async` and Electron does not
  await one, so the quit proceeded; the supervisor's `shutdown` sent `quit` without ever sending
  `stop` and gave the helper 2 s before SIGKILL (its stop bound is 20 s); the helper's `quit`
  handler calls `stop(reason:)` — which is asynchronous — and then `exit(0)` on the next line.
  Result: `display.mp4` with no `moov`, no `events.json`, no `anchors.json`; the library then
  lists the take as "no anchors.json — not a recording". Same outcome from closing the window
  (which on macOS ALSO shut the helper down while the app stayed alive, so a Dock-reopened window
  had a permanently dead recorder: every Record failed with "helper already exited").
- **Fix (b4de440):** `shutdown()` stops a live recording first and waits (bounded by the request
  timeout every stop already has); `before-quit` holds the quit until that finishes and re-issues
  it; `window-all-closed` ends a take in flight and leaves the helper alive on macOS. The stand-in
  helper gained a command log and a stop *delay* — with an instant stop the E2E passed against the
  broken `before-quit` because the whole chain fitted inside the quit's own window.
  Watched failing: unit `["start","quit"]`, E2E `["start","stop"]`; then green.
- **Still open on the Swift side:** P1 — the helper's own `shutdown` still exits before its stop
  completes, so SIGTERM or a parent that dies without the new stop-first path loses the take.

### 2. A helper that cannot be spawned crashed the app; so could a write to a dying one — FIXED
- **Where:** `app/src/helper-client.ts` constructor (no `error` listener on the child or its stdin).
- **Failure:** `helper/build/stc-helper` missing or unexecutable (fresh clone, failed build) →
  `spawn` emits `error`, no listener → uncaught exception in the Electron main process, which
  Electron reports as a modal error dialog: no usable window ever appears. Reproduced here through
  Playwright against the old client: `firstWindow` times out. Second shape: helper crashes, Stop is
  clicked within the exit window → `write EPIPE` on stdin, same uncaught path. A third, found by
  the E2E: with the client fixed, the supervisor burns all its restarts in milliseconds and emits
  `gave-up` before the page exists, so the window appeared and said nothing.
- **Fix (2e159fd):** both route through an idempotent exit path; the spawn error is kept as the
  helper's last words so `gave-up` says `spawn ENOENT`; a waiting `ready()` is rejected by the death
  rather than by its own 10 s timer; the supervisor's unawaited ready promise is marked handled
  (it was an unhandled rejection on every respawn, latent before). `app/test/helper-client-errors.test.ts`
  needs no binary. **2e33f99** adds the renderer half: on load it reads the supervisor's state and
  alerts on `failed`, instead of relying on having been there when the event fired.
  `app/test/missing-helper.e2e.test.ts` launches the real app against a path that does not exist;
  watched failing against the old client (no window) and against the client fix alone (silent).

### 3. A take with no cursor track looked like a good one — FIXED (UI half)
- **Where:** `app/src/renderer.ts` warning handler (matched five codes, dropped the rest);
  `helper/src/Capture.swift:432` (`event-tap-unavailable`), `:336` (`showsCursor = false`).
- **Failure:** Input Monitoring not granted → `CGEvent.tapCreate` returns nil → helper warns once

  only trace. `stream-stopped` had the same shape: the display stream dies, the helper stays in

- **Fix (5c16271):** named codes get a sentence saying what it costs and what to do; unknown codes
  are shown by name; the idle watcher's `display-reconfigured` stays quiet (while recording it is
  accompanied by `display-change-during-recording`, which speaks). Watched failing 2/3, then 3/3.
- **Still open:** P4 — the helper should stop the take on `didStopWithError` as it does on a
  display change, instead of staying in `recording` with a dead stream.

### 4. Every display-only take is labelled as a camera failure — PROPOSED (Swift)
- **Where:** `helper/src/AnchorsDoc.swift:42,70` always writes `camera: {present: false}`;
  `schema/anchors-2.schema.json:122` says *absent* means not attempted and `present:false` means
  attempted and yielded nothing; `app/src/takes.ts:83-92` returns a summary whenever the block

- **Failure:** record anything with the camera toggle off → the library row says the camera

  `anchorsDocument(camera: nil)`); not run, no helper here.
- **Status:** P2. The fix belongs where the knowledge is — `CaptureSession` knows `wantCamera`.

### 5. A `stop` during `starting` leaks a running capture and never answers the `start` — PROPOSED (Swift)
- **Where:** `helper/src/main.swift:106` (`guard self.state == .starting else { return }`).
- **Failure:** `start` (seq 1) then `stop` (seq 2) before `started` arrives. `stop` runs against a
  session whose stream is nil, answers, writes sidecars with zero geometry, sets `capture = nil`.
  The SCK callback then completes the start: `setupWriter()` re-creates `display.mp4`, the stream
  starts, the tap thread starts, and the success branch returns *without sending anything*.
  Seq 1 times out at the client 30 s later; the stream and tap keep running for the life of the
  process (the tap thread holds the session strongly inside `CFRunLoopRun`). The UI cannot reach
  this (Record is disabled until `start` resolves) but the protocol can, and the helper's own rule is
  that every request is answered exactly once.
- **Status:** P3.

### 6. A scrub could end on the wrong frame — FIXED
- **Where:** `transform/src/preview.ts` `draw()` dropped any request that arrived mid-draw.
- **Failure:** paused, drag the scrubber. The last input event lands while the previous draw is
  awaiting the decoder; dropped, nothing draws the final `t`; the canvas shows an earlier frame
  while the clock — and a mark-in taken from `currentNs` — says the later one. Playback hid it
  (next tick redraws).
- **Fix (2880a4d):** coalesce, never drop: one in flight, and a request arriving mid-draw is served
  once it lands at whatever `tNs` is by then. The E2E fires the burst from inside the page;
  against the old player it settled on the *first* value's frame. Watched failing, then green.

### 7. `export:write` could overwrite the take's own files — FIXED
- **Where:** `app/src/main.ts` `export:write` accepted any leaf name ending `.mp4`/`.json`.
- **Failure:** a renderer bug or a hostile renderer names its export `display.mp4` → the recording
  is replaced by its own render. "Source media is never mutated" was true of the renderer's
  behaviour, not of the boundary.
- **Fix (87e7070):** refused by name at the IPC handler. E2E drives the bridge directly; six names
  accepted before, refused after, legitimate name still written.

### 8. Both sinks re-derived frame selection; two copies of one formula — FIXED
- **Where:** `transform/src/export.ts` and `preview.ts` called `frameIndexAt()` themselves after
  `render()` had returned `fs.frameIndex`; `export.ts` carried its own `floor(lastNs*fps/1e9)+1`
  beside `trim.ts`'s `availableFrames()`.
- **Failure:** identical today. The day `render()`'s selection changes (trim-aware, per-track), the
  sinks keep the old rule and disagree with the transform silently — the exact defect class the
  gates exist for, one layer below where they look.
- **Fix (9b07138):** sinks use `fs.frameIndex`; one `availableFrames`. Export, preview, manage and
  camera-toggle E2E green.

### 9. The supervisor heals one direction only — PROPOSED
- **Where:** `app/src/supervisor.ts:126` (`recording` → `idle` heals; `idle` → `recording` does not).
- **Failure:** `start` times out client-side (30 s; a cold `SCShareableContent` can do it) but the
  helper then succeeds. Heartbeat says `recording`, supervisor says `idle`, UI shows Record; click

### 10. Two definitions of a take's duration — low

## 5. The rules the code already follows

Stated as rules; confirm or correct.

**Boundary.** The rule appears to be: *the helper owns every device and every timestamp; main owns
every path, every preference and the helper process; the renderer owns pixels and never sees a
path, a file or node.* Data crosses helper↔main as JSON lines — `seq`-echoed on fd3 for anything
that must not be lost, drop-oldest on stdout for telemetry — and main↔renderer as bytes on channels
enumerated once in `preload.ts`. Applied to a new file: if it names a path it is main; if it
touches `document` it is the renderer; if it touches a device or `mach_absolute_time` it is Swift.
`tsconfig.browser.json`/`tsconfig.node.json` make the second and third of those type errors.

**Pure core vs. sink/process.** The rule appears to be: *if it can be written as a function of data
already read, it goes in `transform/src/` (or the Swift equivalents `CaptureDecisions`,
`CaptureGeometry`, `AnchorsDoc`, `Ring`, `WriterGate`) and is tested with fixtures; only the act of
reading, writing, scheduling or waiting stays in the sink or the callback.* The Swift side does this
by extraction — "the decision itself lives in CaptureDecisions.swift so it can be tested without a
live stream" — and compiles each pure file into a tiny harness binary in `helper/test/<name>/`.
It is the same rule the transform lives by, arrived at independently in a second language.

**Naming and colocation.** The rule appears to be: *`<module>.ts` in `src/`, `<module>.test.ts` in
the sibling `test/`, and the file suffix states the runtime requirement* — `.test.ts` runs
anywhere, `.e2e.test.ts` needs Electron (and runs serialised), `.slow.test.ts` needs minutes,
`.grant.test.ts` needs a TCC grant and is a separate file rather than a skip "because skips read as
covered and rot". `_`-prefixed files are test support, not tests. `scripts/*-gate.mjs` are gates
and take their bounds from `gate-bounds.mjs`; every `scripts/*.mjs` has a hand-written `.d.mts`
guarded by `declaration-drift.test.ts`. Fixtures are directories named for what they exercise
(`basic`, `offset`, `pip`, `real-session`).

**Every wait has a bound and a reason.** `withTimeout(p, ms, what)`; the two unbounded waits say so
in a comment. Corollary the code enforces: every bound has a fault injector (`STC_*_FAULT`) and a
test that watched it fire, and a bound that fires must say whether it was the machine's fault
(`ENVIRONMENT:`) or ours.

**One value, one place — and where two languages force a copy, a test pins them together.**
`stop-bounds.test.ts` for the stop chain; `take-list.test.ts` for the anchors version; `render-backend`
for the raster flags. The code says this is "the fourth 'one value, two copies' defect fixed in a
single session", which is how I knew to look for the fifth (finding 8).

**Reported, never silently skipped.** Invalid takes are listed with a reason; dropped stats are
counted and announced; a skipped gate prints an annotation; a corrupt sidecar costs the label,
never the recording. Every request is answered exactly once, by whichever path gets there first.

**Versioned documents, readers accept v1..vN, writers emit latest.** `anchors-1/2`, `project-1/2`,
`events-1`; `loadSession`, `parseProject` and `takes.ts` each accept both.

**The comment states the failure the code prevents, with date and ticket.** The codebase is a lab
notebook; the CLAUDE.md traps section is its index. This is the single most valuable convention
here and it is why a reviewer with no Mac could still find real defects.

**Where the code breaks its own rules** (the high-value inconsistencies):
1. "Reported, never silent" — the renderer discarded most helper warnings (finding 3, fixed).
2. "Every request answered exactly once" — `start` completed after a `stop` answers nothing
   (finding 5).
3. "Every wait has a bound" — the helper's `shutdown` has *no* wait at all before `exit` (P1).
4. "One value, one place" — `availableFrames` twice, frame selection re-derived in both sinks
   (finding 8, fixed); the "inside the recordings root" check four times, all `startsWith`, which
   passes `stc-evil` as a sibling and `..` segments (P9).
5. "Versioned documents mean what the schema says" — `anchors.camera` is always written though the
   schema defines absence (finding 4).
6. The compositor's own comment described a configuration the sinks do not share (fixed).
7. "A test seam must be a world the fake can be true in" (`_fake-helper.mjs`'s stated rule) — the
   fake's instant `stop` made the quit path untestable; it now has a delay.

## 6. Proposals (not done; each with the tradeoff)

**P0 — Write the brief into the repo.** `docs/BRIEF.md` or `decisions.md`: the prompt's locked
decisions, each marked holds / planned / rejected, cross-referenced to PHASE-1's table. Tradeoff: a
day of writing, and it forces the macOS-26/WebGPU/SolidJS decisions to be reconciled with a
toolchain that cannot currently build for them. Everything in section 7 depends on which of those
decisions are real.

**P1 — Helper `shutdown` must wait for its stop.** `helper/src/main.swift:253-258`: replace the
inline `stop(reason:)` + `exit` with a stop whose completion sends `bye` and exits, backstopped by
`CaptureSession.stopTimeoutSeconds` so a wedged writer still exits. Tradeoff: a `quit`/SIGTERM
during a take now takes up to 20 s; the supervisor's 2 s grace must rise to match, or keep relying
on the TS-side stop-first (landed) and treat this as the belt to its braces. Cannot compile here.

**P2 — Omit `anchors.camera` when no camera was requested.** Thread `wantCamera` from
`CaptureSession.start` into `writeSidecars` → `anchorsDocument(camera:requested:)`; write the block
only when requested; update `helper/test/anchors/main.swift` check 1 (it currently pins the wrong
behaviour) and add a "requested, no frames" case. Tradeoff: none functionally — `takes.ts` and the
schema already expect this; one Swift test flips.

**P3 — Answer a `start` that completes after a `stop`, and tear the session down.**
`main.swift:106`: in the `.success` branch when `state != .starting`, call
`session.stop(reason: "stopped-during-start") { _ in }` and
`IO.send("error", seq: seq, ["code": "stopped-during-start"])`. Tradeoff: the sidecars the earlier
stop wrote get rewritten by this second stop; acceptable, they describe the same (empty) take.

**P4 — Stop the take on `didStopWithError` while recording.** `Capture.swift:395-400`: after
`finishStart`, if the start had already completed, invoke an `onStreamDied` closure that `App` sets
(mirroring `Watchers.onDisplayChange`) to run `stop(reason: "stream-stopped")`. Tradeoff: a
transient SCK error that would have recovered now ends the take; SCK does not resume a stopped
stream, so there is nothing to recover.

**P5 — Stamp the transform version into the project and the export manifest.** A `transform: {
version, cursorOmega, simHz }` block (or a single version integer with a table) so a re-render after
an easing change is explainable, and so a future segment/retake can say which transform produced
which pixels. Schema change (`project-3`), hence not done. Tradeoff: one more field to carry; it
pays for itself the first time `OMEGA` changes.

**P6 — Heal `idle → recording` in the supervisor.** On a heartbeat saying `recording` while the
supervisor says `idle`, set `recording` and fetch the session dir with a `status` request.
Tradeoff: a stand-in that fakes its heartbeat (as the old test did) becomes able to lie the other
way; the fake-helper test pattern already guards that.

**P7 — Multi-display: record origin changes, do not filter by id.** The tempting fix for "an
unrelated monitor stopped my take" (`main.swift:25-34` ignores which display changed) is wrong:
removing another display can move the captured display's global origin and every later event.
The real fix is an origin timeline in `anchors` (or events) that `render` consults per `t`. That is
a schema change and needs a second display to verify (STC-247). Tradeoff: until then, stopping on
any change stays correct and stays annoying.

**P8 — `SeekingFrameSource.close()` during an in-flight seek.** `seeking-frame-source.ts:178-184`
nulls the decoder under a seek parked in its 50 ms wait; on resume `pump()` dereferences it
(`d.decodeQueueSize` at `:159`) and throws a `TypeError` out of a player already closed — an
unhandled rejection, harmless. One-line fix: `this.ticket++` at the top of `close()` so the loop's
own supersession check resolves it null. **Reverted from this branch** because two E2E attempts
(close during playback, close during a backward scrub) did not reproduce it on the old code; the
window is milliseconds and I would not commit a fix I could not watch fail.

**P9 — One `assertInsideRoot(env, dir)` in `takes.ts`** using `path.relative`, replacing the four
`startsWith(root)` checks (`main.ts:150,175,258`, `takes.ts:213`). Tradeoff: a small refactor across
two modules; it is a hardening, not a live bug, because only our own renderer calls these.

**P10 — Make `npm test` degrade rather than refuse without `swiftc`.** Run the Swift build in the
`helper`/`e2e` projects' setup only, so the 223 pure tests still report on a machine without the
toolchain. Tradeoff: exactly the partial-green trap this repo has learned to fear; it would need a
loud "helper tests DID NOT RUN" annotation in the style of the gates.
